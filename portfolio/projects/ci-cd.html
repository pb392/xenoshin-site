Tested release pipeline

A containerized web app that could only reach users after its tests passed, with a separate QA environment updated first.

Code & evidence

What I built

  • GitHub Actions ran unit, integration and real-browser tests on two processor types before building and publishing each Docker image.
  • Pushing to the QA branch updated a QA site automatically; merging into main updated production. Production stayed unchanged until that merge.
  • The workflow then checked over HTTPS that the expected commit was actually running.
  • The server only allows SSH-key logins for a non-root account; root and password logins are refused.

Why it matters for game teams

Game studios ship builds constantly. The same idea, where nothing reaches players until the checks pass, is the core of build and release engineering.
